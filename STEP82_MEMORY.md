# Производственный бот — контрольная память шага 82

## Назначение этапа
Шаг 82 не удаляет накопленный функционал шагов 1–81. Он перестраивает ежедневную работу вокруг понятного интерфейса, строгой изоляции фирм, точного физического местонахождения запасов, подтверждаемых перемещений и безопасного импорта Excel.

## Интерфейс Mini App
Нижнее меню: **Производство · Склад · План · Отчёты · Ещё**.

- **Производство**: рабочее место пользователя, выбор доступной площадки/участка/отдела/места хранения, затем разрешённая операция, позиция и количество. Старый подробный ввод сохранён как расширенный режим.
- **Склад**: общий остаток и физическая раскладка по населённым пунктам, площадкам, участкам, отделам и местам хранения; передачи, инвентаризация, критические остатки.
- **План**: существующие задания, смены, план/факт, потребность и дефицит.
- **Отчёты**: прежние отчёты плюс табличные ведомости и безопасный Excel-импорт.
- **Ещё** сгруппировано: «Люди и доступ», «Работа», «Качество и техника», «Настройка организации», «Безопасность и сервис». Недоступные пользователю пункты скрываются и дополнительно блокируются сервером.

## Мультитенантность / фирмы
- Каждая фирма — отдельный tenant/контур данных.
- Пользователь фирмы A не может получить справочники, склад, отделы, отчёты, передачи или API фирмы B.
- Даже знание чужого `chat_id`, `account_id`, `entity_id`, `department_id`, `area_id` или `storage_location_id` не даёт доступа: сервер повторно проверяет принадлежность tenant.
- Создатель Telegram-группы получает полный tenant-административный доступ к учёту своей группы, но не системные права платформы.

## Системный владелец платформы
`OWNER_TELEGRAM_ID=2097006037` — только корневой системный владелец.

- В обычном интерфейсе он **не получает автоматический доступ к фирмам** и работает на общих основаниях.
- Только ему в Telegram показывается отдельная кнопка **«🔐 Системное меню»**.
- Через системное меню доступны обзор фирм, состояние платформы, критические события и версия.
- Системное меню не смешивается с обычным меню фирмы.
- Версия бота/Mini App показывается только в системном Telegram-меню: Bot 82 / Mini App `20260812a` / `tenant-isolation v2`.
- Обычным пользователям и владельцам фирм версия не показывается в Mini App, `/health` или заголовках.

## Физический склад
Добавлена иерархия:
**населённый пункт → площадка/производство → участок → отдел → место хранения**.

Старый агрегированный остаток сохранён для совместимости. Поверх него `inventory_allocations` хранит точную физическую раскладку. Для старых записей без детализации показывается «нераспределённый/legacy остаток», пока его не уточнят инвентаризацией или перемещением.

## Передачи между подразделениями
Двухсторонняя схема:
1. Отправитель формирует передачу и позиции.
2. Количество резервируется у источника и получает статус **«в пути / ожидает приёмки»**.
3. Остаток получателя не увеличивается до подтверждения.
4. Получатель пересчитывает фактическое количество.
5. При расхождении обязательна причина.
6. После приёмки одной транзакцией создаются складские движения и точная физическая раскладка.
7. Повторная приёмка той же передачи запрещена.

## Excel
### Импорт
- Поддержка XLSX/XLSM через openpyxl.
- Сначала только анализ: файл **не меняет базу**.
- Распознаются неделя, дата, позиция, тип позиции, единица, приход, производство, расход, остаток и групповые заголовки мест хранения.
- Для непривычных/сомнительных данных показываются предупреждения.
- Пользователь видит предварительно распознанные строки и только затем нажимает подтверждение.
- Импорт выполняется только tenant-администратором и журналируется.

### Экспорт
Создаётся привычная производственная ведомость:
- № недели;
- дата;
- позиция;
- для каждой физической площадки блок **приход / пр-во / расход / остаток**;
- общий итог.
Можно формировать отдельные ведомости по сырью, деталям, готовой продукции и складским позициям.

## Защита от ошибок и диверсий
- UI скрывает недоступные действия, но безопасность не полагается на UI.
- Сервер проверяет tenant, пользователя, отдел, операцию, позицию, участок и место хранения.
- Передачи и критические изменения используют транзакции и повторную проверку остатка.
- Расхождения требуют причины.
- Excel сначала preview, затем confirm.
- Аудит фиксирует важные действия и актёра.
- Платформенный root не включается автоматически в обычные уведомления фирм.

## Совместимость
- Миграция базы шага 81 → 82 добавочная, старые данные сохраняются.
- Резервное копирование/восстановление включает новые таблицы площадок, мест хранения, точных остатков, передач, Excel-пакетов и tenant-аудита.
- Публичного сайта нет: Telegram-бот + закрытый Mini App.

## Проверки релиза
- Интеграционный тест двухсторонней передачи: резерв, расхождение, приёмка, защита от повторной приёмки.
- Две независимые фирмы: перекрёстный доступ отклоняется; root без tenant-доступа также получает отказ.
- Создатель группы получает tenant-права своей фирмы.
- Фото-подобная Excel-таблица: preview не меняет склад, confirm применяет, экспорт формируется.
- Backup/restore новых таблиц.
- Миграция реальной структуры шага 81 на шаг 82 без потери остатка.
- Python compileall + JS syntax check.
